## Conversion assumptions → Business model redesign

The conversion question prompted the user to re-examine the whole monetization model.

| Option | Description | Selected |
|--------|-------------|----------|
| Conservative ~2% | low-end freemium benchmark | |
| Base ~5% | industry mid | |
| Justified range (2–5%) | band | |

**User's response:** Asked whether freemium was the best model or if a better one existed. After analysis (freemium hybrid recommended, but the consumer-subscription weak spot flagged):
- Chose **"Freemium hybrid, multi-stream"** framing.
- Then **dropped the subscription entirely** — "we don't want this to have the subscription payment model since it's a one time thing for most people."
- Redefined pricing along a **runs/credits axis**: Basic $0.99 (1 run, #1 city only), Plus/mid $9.99 (3 runs, majority target), Premium $29.99 (unlimited). "Always making the app designed to upsell."
- On conversion: "for the one time purchase the conversion rate should be higher, and for the recurring it would be lower since not as many people would want to run it again because of relocation and just pure curiosity."

**Notes:** Subscription-as-moat (visa-policy monitoring) was offered and rejected with the subscription drop. Pricing change cascaded into ROADMAP Phase 8/9, PROJECT, and REQUIREMENTS — all updated this session.
