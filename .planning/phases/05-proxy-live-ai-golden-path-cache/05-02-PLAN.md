<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/live | untrusted POST body (category, cityName, profession) crosses here |
| /api/live → api.anthropic.com | server-held key authenticates; only the proxy ever calls Anthropic |
| web content → LLM → /api/live | web_search returns attacker-influenceable content; must be validated before return |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-key | Information Disclosure | ANTHROPIC_API_KEY | mitigate | Key read only via `new Anthropic()` from process.env in api/live.ts; never in src/, never in a response body, never logged. Vite `VITE_*` convention deliberately NOT used for this key. |
| T-5-inject | Tampering | cityName/profession in request body | mitigate | `sanitizeInput` constrains cityName/profession to alphanumeric+spaces+punctuation (comma allowed for "City, ST"), max ~100 chars; category validated against the LiveCategory allowlist before any Anthropic call (V5). |
| T-5-llm | Tampering / Information Disclosure | LLM/web_search output | mitigate | `validateItems` runs before every `res.json`; malformed/non-conforming output throws → golden-path fallback. Raw LLM text never reaches the client. |
| T-5-leak | Information Disclosure | error path | mitigate | catch returns golden-path + fromCache:true at 200; internal error details / stack / key never serialized into the response. |
</threat_model>
