<objective>
Self-host the three brand fonts so the visual identity survives a dead hotspot with zero network. Today `index.html` loads Instrument Serif, Manrope, and JetBrains Mono from `fonts.googleapis.com` — a CDN link that REQUIRES network. At the venue ("Internet Access: Not Provided"), if the hotspot drops, the entire typographic identity (a scored rubric item) silently falls back to system fonts. This plan replaces the CDN with bundled `@fontsource` packages and removes the Google Fonts tags, so the fonts ship inside the app bundle.

Purpose: Close ROADMAP Phase 5 Success Criterion #6 (the font half of FOUND-04 offline resilience). The fix carried forward from the Phase 1 cross-AI review.
Output: package.json (+@fontsource deps), src/main.jsx (+@fontsource css imports), index.html (Google Fonts tags removed).
</objective>

CRITICAL — use the STATIC @fontsource/* packages, NOT @fontsource-variable/*:
The `@fontsource-variable/*` packages register the CSS family names 'Manrope Variable' and 'JetBrains Mono Variable' (with the "Variable" suffix), which do NOT match the bare 'Manrope'/'JetBrains Mono' strings the app's font-family declarations use. With the variable packages, 2/3 fonts would silently fall back to system fonts even after self-hosting — SC6 fails. The STATIC `@fontsource/*` per-weight CSS files register the BARE family names ('Manrope','JetBrains Mono','Instrument Serif') that src/ already references, so NO font-family CSS change is needed and offline rendering is correct.

Chosen self-host strategy (static per-weight imports = bare family names, exact CDN coverage):
- @fontsource/manrope          -> import the static per-weight css: 300, 400, 500, 600, 700, 800 (registers family 'Manrope')
- @fontsource/jetbrains-mono   -> import the static per-weight css: 400, 500, 600 (registers family 'JetBrains Mono')
- @fontsource/instrument-serif -> single-weight (400) family; import the regular + 400-italic css (registers family 'Instrument Serif', covering ital@0 and ital@1)
