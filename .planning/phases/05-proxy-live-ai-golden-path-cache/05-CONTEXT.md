Make the live-AI layer real and demo-proof. Build the Vercel serverless proxy that calls Anthropic (with web_search) so the API key never touches the client, wire the three live categories into the already-stubbed `src/` AI sections, and build a bundled golden-path cache that renders instantly when the hotspot dies on stage.

<decisions>
## Implementation Decisions

### Fallback architecture (FOUND-04 / LIVE-04)
- **D-01: Two-layer fallback, single source file.** The golden-path JSON (`data/golden-path/demo-results.json`) is the single source of truth, imported in BOTH places:
  - **Client-bundled** — guarantees instant render when the proxy is unreachable (hotspot dead). This is the SC4 guarantee.
  - **Proxy-embedded** — the serverless function also holds the same JSON and returns it with `fromCache: true` when Anthropic fails but the proxy itself is reachable (SC5).
- **D-02: Client fallback triggers on ANY failure** — fetch timeout (~7s budget tuned for hotspot latency), non-200, network error, or malformed/unparseable response. On any of these the client falls back to the bundled JSON. No path leads to a blank or broken panel.
- **D-03: `fromCache` is internal-only.** Logic/telemetry flag, not surfaced in the UI (see D-08).

### Live-load trigger & UX (LIVE-01/02/03)
- **D-04: Explicit "Pull live data" button** on the city-detail panel — the presenter clicks it; judges watch real listings stream in via hotspot. Deliberate on-stage control, dramatic wow moment, no surprise spinner mid-flow. NOT auto-fetch on city open.
- **D-05: Parallel fan-out with per-category skeletons.** One click fires all shipped categories concurrently; each panel shows a skeleton placeholder and resolves independently as its response returns (or falls back). One slow/failed category never blocks the others.

### Golden-path cache scope (FOUND-04)
- **D-06: Demo persona × 2 cities.** Cache the one rehearsed demo profile across the **#1 US match + 1 international city** (the "living abroad" wow — Lisbon is the working assumption; confirm against the demo script). Covers all categories that ship (D-09).
- **D-07: Generated by a capture script, not hand-authored.** A script (e.g. `scripts/capture-golden-path`) calls the REAL proxy once and snapshots the output to `demo-results.json`, so cached output is byte-for-byte the shape of live output. Re-runnable to refresh before pitch day.

### Category scope
- **D-09: Ship the 3 required categories only** — `jobs`, `housing` (`housing_rent` | `housing_buy` chosen by the profile's housing preference), and `dayinlife` (narrative). Defer `nightlife` / `outdoors` / `food` (they exist in the `LiveCategory` contract but are out of scope for Phase 5).

### On-stage presentation
- **D-08: Cached fallback is visually invisible.** When the fallback fires, panels render identically to live — no "cached"/"offline" badge, no "as of" tag. Keeps the demo seamless if the hotspot drops mid-pitch (SC4: "render instantly, no blank state"). `fromCache` stays internal.
- **D-10: Listing cards show source name, not clickable links.** Each job/housing card displays title + salary/rent + source name (e.g. "Indeed", "Idealista") as styled text, NOT an `<a>` anchor. Honors the competition see-not-click rule and removes misclick risk on stage. Real source URLs may be stored in the data but are never rendered as live links.

### Claude's Discretion (defer to research/planning)
- Anthropic **model choice** for the live calls (cost/latency matters to Gabriel — Haiku is the cost/speed default, but the researcher must confirm `web_search` tool support and quality per model on a hotspot connection).
- `web_search` tool configuration, prompt design per category, and the LLM-output validation/sanitization schema (api/README already mandates: assume malformed, validate before returning).
- Exact timeout value (D-02 says ~7s as a starting budget — planner/executor tunes against real hotspot latency).
- Skeleton/loading visual treatment (must match the existing dark theme; reuse existing components).
</decisions>

- **Vercel serverless in `/api`** — one deploy, key as Vercel env var (Phase 1). No separate backend server.
- **TS at the network boundary, JSX in UI** — proxy + cache loader in TS (`api/`, `shared/`), React wiring in JSX (`src/`).
- **"as of [date]" labeling** — `CityDetail.jsx` already uses `FX_AS_OF`; the financial layer shows data provenance. (Note: live panels deliberately do NOT show a cache tag — D-08.)

### Integration Points
- New `api/live.ts` (or per-category endpoints) — the proxy. Client calls `/api/...`, never `api.anthropic.com`.
- New `data/golden-path/demo-results.json` — the cache, imported by both the client bundle and the proxy.
- New `scripts/capture-golden-path` — generates the cache from a real proxy run (D-07).
- `.env.example` — document `ANTHROPIC_API_KEY` (and any web_search config) as a required Vercel env var.

## Specific Ideas
- The "Pull live data" button is a deliberate **demo theater** moment — frame it so judges register "this is pulling real, current data right now." Real on a working hotspot; seamless cache when not (they can't tell — D-08).

- International city in the cache (Lisbon working assumption) doubles as the offline "living abroad" proof — ties the live layer to the premium/international story.
