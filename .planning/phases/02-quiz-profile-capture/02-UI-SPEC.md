## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, dot indicator padding |
| sm | 8px | Pill gaps, inline badge padding, tight row gaps |
| md | 16px | Default element spacing, input horizontal padding, pill horizontal padding |
| lg | 24px | Section bottom margin (`sectionGap` = 28px — see exception), progress bar margin |
| xl | 32px | Step container padding, CTA button top margin |
| 2xl | 48px | Major section breaks (e.g. between "Going Global" group and prior step) |
| 3xl | 64px | Page-level padding-bottom (scroll clearance) |

Exceptions:
- `sectionGap` = 28px (existing prototype value — preserve as-is, not 24px or 32px)
- Touch targets for Yes/No toggles: minimum 44px total height (6px top + bottom padding + 32px text = 44px minimum; current prototype uses `padding:"6px 16px"` which meets this on desktop)
- Progress bar height: 3px (decorative, not a spacing token)
- Progress bar gap between segments: 4px (xs)

| Band | Tokens | Note |
|------|--------|------|
| 60% dominant | `--bg` (#08090C) | All page backgrounds, scroll areas |
| 30% secondary | `--surface` + `--card` + `--card-hover` | Card shells, inputs, nested panels |

### Accent Reserved For (explicit list)

`--accent` (#6EE7B7) is used ONLY on:
1. The `btnPrimary` background (CTA button fill — text becomes `#08090C` on this background)
2. Active pill border (`1.5px solid var(--accent)`)
3. Active pill text color
4. Progress bar filled segments
5. Positive savings value in results (alias of `--pos`)
6. Income / savings slider `accentColor`
7. Logo diamond icon (`◆`) on landing and header
8. Inline monetary value highlights in field labels (the `<span>` with JetBrains Mono)
9. "Going Global" group accent marker (new — see component spec below)
10. Tension reconciliation follow-up panel left-border (new — see component spec below)

`--accent` must NOT appear on: body text, secondary labels, borders of inactive elements, decorative separators.

### New Semantic Additions for Phase 2

## Primitive Inventory

These are the source-of-truth styled primitives the rebuild MUST reuse. Copy the exact object shape from `PotentialApp.jsx` and extend only for new use cases.

### `pill(active: boolean)` — toggle button

```js
{
  padding: "8px 16px",
  borderRadius: 10,
  border: active ? "1.5px solid var(--accent)" : "1px solid var(--border)",
  background: active ? "var(--accent-dim)" : "var(--card)",
  color: active ? "var(--accent)" : "var(--text2)",
  fontSize: 13,
  cursor: "pointer",
  fontWeight: active ? 600 : 400,
  transition: "all 0.2s",
  fontFamily: "inherit",
  display: "inline-flex",
  alignItems: "center",
  gap: 6,
}
```

Citizenship shortlist (D-08) uses this primitive at `padding: "10px 18px"` (same as the dependents count pills). The Going Global group citizenship row renders as a `flexWrap: "wrap"` container of pill buttons, identical to the education row pattern.

### `inputStyle` — text input

```js
{
  width: "100%",
  padding: "14px 16px",
  background: "var(--card)",
  border: "1px solid var(--border)",
  borderRadius: 12,
  color: "var(--text)",
  fontSize: 15,
  fontFamily: "inherit",
  boxSizing: "border-box",
}
```

Focus state: border changes to `1px solid var(--border-active)`. No outline. Implement via `onFocus`/`onBlur` handlers updating local border state.

### `btnPrimary` — full-width CTA

```js
{
  width: "100%",
  padding: "16px",
  background: "var(--accent)",
  color: "#08090C",
  border: "none",
  borderRadius: 14,
  fontSize: 15,
  fontWeight: 700,
  cursor: "pointer",
  fontFamily: "inherit",
  letterSpacing: "0.03em",
}
```

Disabled state (`btnDisabled`): swap `background` to `"var(--card)"`, `color` to `"var(--text3)"`, `cursor` to `"not-allowed"`. Do not use opacity.

### `label` — field label

```js
{
  fontSize: 11,
  textTransform: "uppercase",
  letterSpacing: "0.1em",
  color: "var(--text2)",
  display: "block",
  marginBottom: 8,
  fontWeight: 600,
}
```

### `fadeIn` — step transition animation

```js
{
  opacity: anim ? 1 : 0,
  transform: anim ? "translateY(0)" : "translateY(24px)",
  transition: "all 0.7s cubic-bezier(0.16,1,0.3,1)",
}
```

The step/profileStep transition pattern: on navigation, set `anim = false`, wait 60ms (via `setTimeout`), then set `anim = true`. Apply `fadeIn` to the step's root `<div>`. New steps must follow this same pattern — do not use CSS classes or Framer Motion.

### Sliders — `<input type="range">`

- `accentColor: "#6EE7B7"` for income, savings, partner income, openness-to-abroad
- `accentColor: "#F87171"` for debt slider only
- `width: "100%"`, no other overrides
- Range labels: `display: "flex"`, `justifyContent: "space-between"`, `fontSize: 11`, `color: "var(--text3)"`, `marginTop: 4`

### Progress Bar

Segmented bar at top of every quiz step:
- Outer: `display: "flex"`, `gap: 4`, `flex: 1`
- Each segment: `flex: 1`, `height: 3`, `borderRadius: 2`
- Filled: `background: "var(--accent)"`
- Unfilled: `background: "var(--border)"`
- Transition: `"all 0.3s"`

Step counter (right of bar): `fontSize: 12`, `color: "var(--text3)"`, JetBrains Mono.

Back button (left of bar): `background: "none"`, `border: "none"`, `color: "var(--text3)"`, `cursor: "pointer"`, `fontSize: 13`, `fontFamily: "inherit"`. Symbol: `←`.

### B. "Going Global" Step (D-06)

**Purpose:** Differentiation moment on stage. Groups openness-to-abroad + citizenship + move timeline into a narratively distinct step.

**Step heading:** "Going Global" — `Instrument Serif`, 32px, weight 400.

**Step subtitle:** "This shapes whether international cities appear in your matches — and which visa pathways open up." — `Manrope`, 14px, `var(--text3)`.

**Visual treatment — group accent marker:**
The step uses a single green left-border accent panel to frame the three sub-fields as a visual unit:

```

│ 3px left border: var(--accent)             │
│ paddingLeft: 16px                          │
│ marginBottom: 28px                         │
│ background: transparent                    │

│  [MOVE TIMELINE]                           │
```

Implementation: `borderLeft: "3px solid var(--accent)"`, `paddingLeft: 16`, `marginBottom: 28`.

**Sub-field 1 — Openness to Living Abroad (D-10)**

- `label` primitive: "Open to living abroad"
- Value readout (inline in label): `<span style={{ ...mono, color:"var(--accent)" }}>{value === 0 ? "Not at all" : value <= 30 ? "A little curious" : value <= 70 ? "Definitely open" : "Ready to go"}</span>`

**Sub-field 2 — Citizenship (D-08)**

- `label` primitive: "Citizenship"
- Shortlist pills (flexWrap wrap, gap 8): US Citizen (default selected), Canadian, British, Australian, EU Citizen, Indian, Mexican, Filipino, Brazilian, Nigerian, Other.
- Default: `"US Citizen"` pre-selected (pill active state on load).
- US Citizen selection: `immigrationStatus` auto-sets to `"citizen"` — no follow-up question shown.
- Non-US selection: a conditional sub-row appears below the citizenship pills (same `fadeIn` animation, 60ms delay):
  - `label` primitive: "Current immigration status (US)"
  - Pills: `"US Citizen"`, `"Permanent Resident"`, `"Work Visa (H-1B / O-1 / etc.)"`, `"Student Visa"`, `"Other / Not in US"`

- Single-select. Stores to `profile.moveTimeline`.
- "Just exploring" selection: no visual penalty; it is a valid timeline value.

**Step validation:** Progress requires `profile.citizenship` to be set (it defaults to `"US Citizen"` so the step is always completable without user action — consistent with D-09).

### E. Conditional Tension Reconciliation Follow-Up (D-03, D-14)

**Trigger condition:** After the user completes the Lifestyle step AND the Motivations step, the quiz evaluates for conflicting priority pairs. Phase 2 detects and surfaces exactly one conflict at a time (highest-confidence conflict if multiple exist). Detection logic is defined in the planner's task — the UI spec only covers the visual treatment.

**Placement:** The reconciliation panel appears as an injected sub-step WITHIN the existing step frame — it does not get its own progress-bar step. It appears between Motivations step and Priorities step, animated in with `fadeIn`.

**Reconciliation Panel Layout:**

```
┌──────────────────────────────────────────────────────┐
│  3px left border: var(--accent)                      │
│  background: var(--card)                             │
│  borderRadius: 16                                    │
│  padding: 20                                         │
│  border: 1px solid var(--border-active)              │
│                                                      │
│  [LABEL] We noticed something                        │
│  [HEADING — Instrument Serif 24px]                   │
│    "You love {dimension A} and {dimension B}."       │
│  [BODY — Manrope 14px, text2, lineHeight 1.6]        │
│    "These sometimes pull in different directions.    │
│     If you had to lean one way, which wins?"         │
│                                                      │
│  [PILLS — single select, two options]                │
│    "{dimension A label}"  |  "{dimension B label}"   │
│                                                      │
│  [SMALL TEXT — text3, 12px]                          │
│    "This helps us rank cities that balance both —    │
│     and flag the ones that can't."                   │
└──────────────────────────────────────────────────────┘
```

Label styles: `label` primitive (uppercase, 11px, `var(--text2)`). Content: "We noticed something".

Heading: `Instrument Serif`, 24px, weight 400 — NOT the step-level 32px.

The two reconciliation pills use the standard `pill(active)` primitive at full width:
```js
{ ...pill(active), flex: 1, justifyContent: "center", padding: 14 }
```

Rendered in a `display: "flex"`, `gap: 10` row.

Resolution stored as: `profile.tiebreaker = { dimension: "A" | "B", pair: [dim_A_key, dim_B_key] }`.

If no conflict detected: this panel is skipped entirely, no gap or placeholder is shown.

**Skip affordance:** Small text link below the panel: "Skip — I'm equally pulled both ways". Styles: `fontSize: 12`, `color: "var(--text3)"`, `cursor: "pointer"`, `textDecoration: "underline"`. Click sets `profile.tiebreaker = null` and advances to the next step.

### F. Branching / Conditional Follow-Up Transitions (D-03)

Conditional sub-fields (e.g., partner income appearing when `hasPartner: true`, immigration status appearing when non-US citizenship is selected) follow this single pattern throughout the rebuild:

1. The containing element conditionally renders when condition is true.
2. Parent re-triggers anim via `setAnim(false)` → 60ms timeout → `setAnim(true)`.
3. The conditional content div carries `fadeIn` style.
4. No CSS `display:none` toggling — use conditional JSX rendering (`{condition && <div>…</div>}`).

This is consistent with the existing prototype pattern for `hasPartner`, `hasDependents`, and `hasPets` conditional sub-fields.

## Layout Constraints

- **Max content width:** 560px, centered via `maxWidth: 560, margin: "0 auto"` — consistent with prototype quiz container.
- **Page padding:** `padding: "32px 24px"` on outer container.
- **Scroll:** `minHeight: "100vh"` on root — no overflow:hidden on body.
- **Grid — lifestyle tags:** `display: "grid"`, `gridTemplateColumns: "1fr 1fr"`, `gap: 10` (existing pattern; retain for all multi-column pill grids with emoji).
- **Grid — single-column pill groups:** `display: "flex"`, `flexWrap: "wrap"`, `gap: 8` (profession pills, education pills, citizenship shortlist, timeline, dealbreakers).
- **Mobile:** The existing app is desktop-first, mobile-responsive via `clamp()` on the landing display font and the flexible grid. Phase 2 does not introduce new breakpoints or media queries. All pill groups must wrap gracefully at 320px viewport width.
