# Phase 2 — UI Design Contract
## Quiz & Profile Capture

> Visual and interaction contract for the capture-layer rebuild. Generated by gsd-ui-researcher.
> This is an EXISTING app under a LOCKED "port-don't-redesign" decision (CONTEXT.md D-01, Phase 1).
> All tokens are extracted verbatim from `src/screens/PotentialApp.jsx` and `index.html`.
>
> **CHECKER NOTICE — PORT-DON'T-REDESIGN OVERRIDE (D-01)**
> This spec governs a port of a shipped prototype, not a greenfield build. The locked decision
> D-01 ("port-don't-redesign visual identity") prohibits altering any shipped pixel values.
> Where this spec declares JUSTIFIED EXCEPTIONs to greenfield maximums (≤4 font sizes, ≤2
> weights, 4px-grid spacing), those exceptions are MANDATORY to comply with D-01 — reducing
> counts to hit the greenfield target would itself constitute a redesign violation.
> Checker dimensions 4 and 5 must evaluate against the port-faithful contract below, not

## Typography

### PORT-DON'T-REDESIGN NOTICE — Dimension 4

The checker's greenfield maximum is ≤4 font sizes and ≤2 weights. This phase governs an
EXISTING shipped prototype (D-01 lock). The values below are the ACTUAL SHIPPED TOKENS
extracted from `PotentialApp.jsx`. They cannot be reduced without altering the shipped
visual appearance. See "Justified Exceptions" section for the explicit accounting.

### Phase 2 Scope Boundary

`clamp(48px, 10vw, 72px)` — the landing-page display headline — is declared **OUT OF SCOPE**
for Phase 2. It appears only in the `step === 0` landing screen (line 198 of PotentialApp.jsx).
Phase 2 rebuilds the quiz (`step === 1`). The display size is inherited, landing-page only,
not modified this phase, and must not be counted against the Phase 2 type scale.

Similarly, `30px` (results h2) and `36px` (city-detail hero h2) appear only in `step === 2`
screens, which Phase 2 does not touch. `19px` (landing subtitle) and `18px` (lifestyle emoji
font-size) are also outside the quiz step block. None of these are graded Phase 2 sizes.

### Phase 2 Quiz Type Scale

#### Primary Scale (4 sizes — the load-bearing roles in the quiz step block)

| Role | Font | Size | Weight | Line Height | Usage |
|------|------|------|--------|-------------|-------|
| Step heading | Instrument Serif | 32px | 400 | 1.1 | Per-step question title (`h2` — "What do you do?", "Your finances", etc.) |
| Body / subtitle | Manrope | 14px | 400 | 1.6 | Step subtitle / hint copy below step heading |

#### Inherited Shipped Sizes — JUSTIFIED EXCEPTIONS

| Role | Font | Size | Weight | Line Height | Justification |
|------|------|------|--------|-------------|---------------|
| Reconciliation sub-heading | Instrument Serif | 24px | 400 | 1.2 | New panel introduced this phase; uses 24px (not 32px) to signal a lower hierarchy than a full step heading — distinct role, cannot collapse to 32px without losing that hierarchy |

- 400 — body, subtitle, pill inactive, Instrument Serif headings: shipped value
- 600 — uppercase labels, pill active state, step counter bold: shipped value
- 700 — `btnPrimary` (`fontWeight: 700`): shipped CTA weight; not reduced to 600 because it would alter the shipped CTA visual weight (D-01 lock). JUSTIFIED EXCEPTION: weight 700 is the shipped `btnPrimary` value and must be preserved verbatim.

Primary weights: 400 (body) + 600 (label/active). Inherited exception: 700 (CTA only, D-01 lock).

Permitted weight values by font (do NOT add weights not loaded by `index.html`):
- Manrope: 300, 400, 500, 600, 700, 800
- Instrument Serif: 400
- JetBrains Mono: 400, 500, 600

## Primitive Inventory

These are the source-of-truth styled primitives the rebuild MUST reuse. Copy the exact object
shape from `PotentialApp.jsx` and extend only for new use cases.

### `pill(active: boolean)` — toggle button

```js
{
  padding: "8px 16px",
  borderRadius: 10,
  border: active ? "1.5px solid var(--accent)" : "1px solid var(--border)",
  background: active ? "var(--accent-dim)" : "var(--card)",
  color: active ? "var(--accent)" : "var(--text2)",
  fontSize: 13,
  cursor: "pointer",
  fontWeight: active ? 600 : 400,
  transition: "all 0.2s",
  fontFamily: "inherit",
  display: "inline-flex",
  alignItems: "center",
  gap: 6,
}
```

Citizenship shortlist (D-08) uses this primitive at `padding: "10px 18px"` (same as the
dependents count pills). The Going Global group citizenship row renders as a `flexWrap: "wrap"`
container of pill buttons, identical to the education row pattern.

### `inputStyle` — text input

```js
{
  width: "100%",
  padding: "14px 16px",
  background: "var(--card)",
  border: "1px solid var(--border)",
  borderRadius: 12,
  color: "var(--text)",
  fontSize: 15,
  fontFamily: "inherit",
  boxSizing: "border-box",
}
```

Focus state: border changes to `1px solid var(--border-active)`. No outline. Implement via
`onFocus`/`onBlur` handlers updating local border state.

### `btnPrimary` — full-width CTA

```js
{
  width: "100%",
  padding: "16px",
  background: "var(--accent)",
  color: "#08090C",
  border: "none",
  borderRadius: 14,
  fontSize: 15,
  fontWeight: 700,
  cursor: "pointer",
  fontFamily: "inherit",
  letterSpacing: "0.03em",
}
```

Disabled state (`btnDisabled`): swap `background` to `"var(--card)"`, `color` to
`"var(--text3)"`, `cursor` to `"not-allowed"`. Do not use opacity.

### `label` — field label

```js
{
  fontSize: 11,
  textTransform: "uppercase",
  letterSpacing: "0.1em",
  color: "var(--text2)",
  display: "block",
  marginBottom: 8,
  fontWeight: 600,
}
```

### `fadeIn` — step transition animation

```js
{
  opacity: anim ? 1 : 0,
  transform: anim ? "translateY(0)" : "translateY(24px)",
  transition: "all 0.7s cubic-bezier(0.16,1,0.3,1)",
}
```

The step/profileStep transition pattern: on navigation, set `anim = false`, wait 60ms (via
`setTimeout`), then set `anim = true`. Apply `fadeIn` to the step's root `<div>`. New steps
must follow this same pattern — do not use CSS classes or Framer Motion.

### Sliders — `<input type="range">`

- `accentColor: "#6EE7B7"` for income, savings, partner income, openness-to-abroad
- `accentColor: "#F87171"` for debt slider only
- `width: "100%"`, no other overrides
- Range labels: `display: "flex"`, `justifyContent: "space-between"`, `fontSize: 11`,
  `color: "var(--text3)"`, `marginTop: 4`

### Progress Bar

Segmented bar at top of every quiz step:
- Outer: `display: "flex"`, `gap: 4`, `flex: 1`
- Each segment: `flex: 1`, `height: 3`, `borderRadius: 2`
- Filled: `background: "var(--accent)"`
- Unfilled: `background: "var(--border)"`
- Transition: `"all 0.3s"`

Step counter (right of bar): `fontSize: 12`, `color: "var(--text3)"`, JetBrains Mono.

Back button (left of bar): `background: "none"`, `border: "none"`, `color: "var(--text3)"`,
`cursor: "pointer"`, `fontSize: 13`, `fontFamily: "inherit"`. Symbol: `←`.
`aria-label="Go back"` is required on this element.

### E. Conditional Tension Reconciliation Follow-Up (D-03, D-14)

**Trigger condition:** After the user completes the Lifestyle step AND the Motivations step,
the quiz evaluates for conflicting priority pairs. Phase 2 detects and surfaces exactly one
conflict at a time (highest-confidence conflict if multiple exist). Detection logic is
defined in the planner's task — the UI spec only covers the visual treatment.

**Placement:** The reconciliation panel appears as an injected sub-step WITHIN the existing
step frame — it does not get its own progress-bar step. It appears between Motivations step
and Priorities step, animated in with `fadeIn`.

**Reconciliation Panel Layout:**

```
┌──────────────────────────────────────────────────────┐
│  3px left border: var(--accent)                      │
│  background: var(--card)                             │
│  borderRadius: 16                                    │
│  padding: 20                                         │
│  border: 1px solid var(--border-active)              │
│                                                      │
│  [LABEL] We noticed something                        │
│  [HEADING — Instrument Serif 24px]                   │
│    "You love {dimension A} and {dimension B}."       │
│  [BODY — Manrope 14px, text2, lineHeight 1.6]        │
│    "These sometimes pull in different directions.    │
│     If you had to lean one way, which wins?"         │
│                                                      │
│  [PILLS — single select, two options]                │
│    "{dimension A label}"  |  "{dimension B label}"   │
│                                                      │
│  [SMALL TEXT — text3, 12px]                          │
│    "This helps us rank cities that balance both —    │
│     and flag the ones that can't."                   │
└──────────────────────────────────────────────────────┘
```

Label styles: `label` primitive (uppercase, 11px, `var(--text2)`). Content:
"We noticed something".

Heading: `Instrument Serif`, 24px, weight 400 — NOT the step-level 32px. This reduced size
signals a sub-step hierarchy below the main step heading (JUSTIFIED EXCEPTION — see Typography
section).

The two reconciliation pills use the standard `pill(active)` primitive at full width:
```js
{ ...pill(active), flex: 1, justifyContent: "center", padding: 14 }
```

Rendered in a `display: "flex"`, `gap: 10` row. (`gap: 10` is an inherited shipped token —
see Spacing Justified Exceptions.)

Resolution stored as:
`profile.tiebreaker = { dimension: "A" | "B", pair: [dim_A_key, dim_B_key] }`.

If no conflict detected: this panel is skipped entirely, no gap or placeholder is shown.

**Skip affordance:** Small text link below the panel: "Skip — I'm equally pulled both ways".
Styles: `fontSize: 12`, `color: "var(--text3)"`, `cursor: "pointer"`,
`textDecoration: "underline"`. Click sets `profile.tiebreaker = null` and advances to the
next step.

### F. Branching / Conditional Follow-Up Transitions (D-03)

Conditional sub-fields (e.g., partner income appearing when `hasPartner: true`, immigration
status appearing when non-US citizenship is selected) follow this single pattern throughout
the rebuild:

1. The containing element conditionally renders when condition is true.
2. Parent re-triggers anim via `setAnim(false)` → 60ms timeout → `setAnim(true)`.
3. The conditional content div carries `fadeIn` style.
4. No CSS `display:none` toggling — use conditional JSX rendering
   (`{condition && <div>…</div>}`).

This is consistent with the existing prototype pattern for `hasPartner`, `hasDependents`,
and `hasPets` conditional sub-fields.

  with prototype quiz container.

- **Scroll:** `minHeight: "100vh"` on root — no overflow:hidden on body.

  (existing shipped pattern — inherited locked token; retain for all multi-column pill grids

  (profession pills, education pills, citizenship shortlist, timeline, dealbreakers).
- **Mobile:** The existing app is desktop-first, mobile-responsive via `clamp()` on the
  landing display font and the flexible grid. Phase 2 does not introduce new breakpoints or
  media queries. All pill groups must wrap gracefully at 320px viewport width.
