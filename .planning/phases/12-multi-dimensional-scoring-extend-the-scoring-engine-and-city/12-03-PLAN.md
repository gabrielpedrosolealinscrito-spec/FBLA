<d07_resolution>
**RESOLVED FORK — missing-data behavior (D-01 vs D-07 conflict at 7/28 cities).** `cities.ts` has 28 cities; only 22 have cited new-category data. RESEARCH gave two contradictory mechanisms for missing data: Pattern-1 samples (`return 0.5` neutral midpoint) vs Pitfall 5 ("skip the factor entirely"). Pitfall 5 assumed exclusion was rare (only San Diego toddler) — that premise is void at 7 missing cities (LA, SF, Boston, DC, Houston, Philadelphia, London).

**Decision (honors both locked decisions):** Use **neutral-midpoint (factorScore returns 0.5 when the city field is absent), and label the emitted scoreFactors entry `dataLevel: 'limited-data'`.** Rationale:
- D-07 ("neither rewarded nor punished, never a phantom zero") → midpoint is exactly neutral; skipping-to-zero would punish flagship cities and tank their rank.
- D-01 ("score only where cited data exists") → the `'limited-data'` label keeps the honesty boundary visible; the UI surfaces it distinctly, never conflated with cited numbers.
- Clamp gate unaffected: midpoint (0.5) < full-data max (1.0), so the binding city for D-05 is still a fully-cited city — Plan 04's gate holds.
The flagship-ranking sanity check (do Boston/SF still read honestly?) is folded into the D-06 manual demo-narrative check already in 12-VALIDATION.md — it is a human judgment, not an asserted invariant.

**Test/mechanism parity (critical):** the factor functions AND the D-07 tests MUST use the same mechanism. A `'limited-data'` city's contribution is `> 0` (midpoint), NOT zero. Write the tests to assert `> 0` for missing-data cities.
</d07_resolution>
