<objective>
Stand up the vitest test infrastructure and write the RED (failing) test scaffolds for the entire engine BEFORE any engine code exists. This is the Wave 0 / Nyquist foundation: every engine module in Waves 2–3 implements against a test that already exists and currently fails. No test runner is installed today (verified: package.json has only react/vite/vercel deps), so this plan installs it behind a blocking package-legitimacy checkpoint.

Purpose: Make the engine and financial math automatically verifiable from the first line of implementation. Per the project's Nyquist rule, eligible logic tasks (federalTax, takeHome, expenses, getMatchScore, dealbreaker penalty/re-confirm) must have automated verification — this plan creates the test files those later tasks turn GREEN.

Output: vitest installed (dev-only), `vite.config.js` test block, `src/test-setup.js`, and four RED `.test.ts` files under `shared/engine/`.

MVP-mode note: This phase is planned under MVP_MODE=true, but the phase's division_of_labor instruction (backend logic owned by Gabriel; a separate friend authors + executes the frontend UI later) takes precedence over strict vertical-slice layering. There is no UI to end-to-end test in this plan, so MVP's "failing happy-path e2e test" is mapped onto the engine integration test `rankCities(profile)` in `index.test.ts` (returns a sorted, non-empty `MatchResult[]`). The ROADMAP Phase 3 Goal is not written in canonical `As a / I want / so that` user-story form; rather than invent one, the derived capability framing is used in the Phase Goal block below and the discrepancy is surfaced here.
</objective>
