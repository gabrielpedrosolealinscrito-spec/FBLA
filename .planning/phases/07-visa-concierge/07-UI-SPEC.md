# Phase 7 — UI Design Contract
## Visa Concierge

> Visual and interaction contract for the Premium-tier visa concierge surface.
> Generated by gsd-ui-researcher.
>
> **PALETTE RULING:** This phase inherits the LOCKED `PotentialApp.jsx` mint-green token system
> (`--accent #6EE7B7`, `--bg #08090C`, etc.) — identical to Phase 2. The `brand/colors.css`
> night→dawn + gold palette informs voice and "calm, cinematic, certain" *direction* but does NOT
> alter the shipped accent hue. Applying gold (`#E2B56B`) as the in-app accent would clash with
> the Phase 6 roadmap and Phase 5 live-data surfaces rendered on the same screen during the demo.
> The brand kit governs pitch assets (deck, social posts); the app token system governs product UI.
>
> **SCREENER NOTE:** The eligibility screener is SILENT (CONTEXT D-01) — there is no form or
> question flow to design. The user clicks into the Visa screen and pathways appear instantly,
> derived entirely from the existing Profile. This spec covers the DISPLAY surface only.

> **CHECKER NOTICE — PORT-DON'T-REDESIGN OVERRIDE (Phase 2 D-01)**
> This spec governs a screen in an existing app under the "port-don't-redesign" visual identity
> lock established in Phase 1 / Phase 2. The shipped prototype defines the token system, type
> scale, primitives, and animation contract. This spec INHERITS those values verbatim.
>
> Where this spec declares JUSTIFIED EXCEPTIONs to greenfield maximums (≤4 font sizes, ≤2
> weights, inline-style-only architecture), those exceptions are MANDATORY to comply with the
> Phase 2 lock — reducing them to hit greenfield targets would itself constitute a redesign
> violation. Checker dimensions 4 and 5 must evaluate against the inherited contract below,
> not the greenfield maximums.

### 60/30/10 Split

| Band | Tokens |
|------|--------|
| 60% dominant | `--bg` (#08090C) — all page backgrounds, scroll areas |
| 30% secondary | `--surface` + `--card` + `--card-hover` — all card and panel shells |
| 10% accent | `--accent` ONLY (strictly reserved — see below) |

### Accent Reserved For

`--accent` (#6EE7B7) is used ONLY on (Phase 7 additions in bold):
1. The `btnPrimary` background (CTA button fill)
2. Active pill border and text
3. Progress bar filled segments
4. Positive savings values
5. Income/savings slider `accentColor`
6. Logo diamond (`◆`)
7. Inline monetary value highlights
8. **"Strong fit" badge text and left-border marker**
9. **Pathway column left-border accent marker (strong-fit pathway only)**
10. **Checklist item check icon (`✓`)**

`--accent` must NOT appear on: body text, secondary labels, decorative separators, "Possible" badges, "Long shot" badges.

### Phase 7 Net-New: Graded Fit Badge (D-03)

Three badge states. No new color tokens — all mapped to existing tokens.

| Grade | Text Color | Background | Border | Usage |
|-------|-----------|------------|--------|-------|
| Strong fit | `var(--accent)` #6EE7B7 | `rgba(110,231,183,0.08)` (= `--accent-dim`) | `1px solid rgba(110,231,183,0.15)` | "Strong fit — your remote income likely clears the D8 minimum" |
| Possible | `var(--accent2)` #FBBF24 | `rgba(251,191,36,0.08)` (= `--warn-dim`) | `1px solid rgba(251,191,36,0.15)` | "Possible — Express Entry favors a younger applicant with a degree" |
| Long shot | `var(--text2)` #8896AB | `var(--surface)` #111318 | `1px solid var(--border)` | "Long shot — [named gating factor]" |

**Reasoning for "Long shot" using `--text2` (not `--neg`):** `--neg` (#F87171) reads as denied / error, which conflicts with the UPL "informational assessment, not a legal determination" framing (CONTEXT D-03). "Long shot" is a likelihood signal, not a rejection. Neutral `--text2` is accurate and legally defensible.

Each column is a `var(--card)` background card:
```js
{
```

## Layout Constraints

- **Max content width:** 720px, centered via `maxWidth: 720, margin: "0 auto"`.
- **Page padding:** `padding: "24px 24px 64px"` on outer container.
- **Comparison grid:** `gridTemplateColumns: "repeat(auto-fit, minmax(300px, 1fr))"`, `gap: 16`. Columns render side-by-side above ~630px; stack automatically below that — no `@media` query needed or permitted (inline-style architecture).
- **Scroll:** `minHeight: "100vh"` on root — no `overflow: hidden` on body.
- **Off-screen content:** the full checklist and source block may require scroll on smaller laptops — this is acceptable. Do NOT truncate checklist items.
