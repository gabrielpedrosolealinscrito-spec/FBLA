# Phase 8 — UI Design Contract

> Visual and interaction contract for the freemium tier gate. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — inline-style JSX, CSS custom properties per-screen |
| Icon library | inline SVG only (no library; matches existing padlock / map-pin pattern) |
| Font | Instrument Serif (serif, display/headings) · Manrope (sans, body/UI) · JetBrains Mono (mono, numbers/badges) — self-hosted via @fontsource/* |

**Rationale for Tool: none:** The project has an established design system of inline-CSS JSX with scoped CSS custom properties (`--bg`, `--accent`, `--ink`, etc.) defined per-screen. RESEARCH.md is explicit: no new packages; no Framer Motion, Radix, Headless UI, or icon libraries. Initializing shadcn would break the existing pattern on a battery-dependent demo device.

Source: RESEARCH.md Standard Stack section, confirmed by direct inspection of ResultsMap.jsx and Landing.jsx CSS blocks.

Declared values (must be multiples of 4):

| Token | Value | Usage in Phase 8 |
|-------|-------|------------------|

| sm | 8px | Padding inside RunsBadge pill; gap between pill tier buttons |

Exceptions:
- LockGate padlock overlay: `inset: 0` with `border-radius: 14px` — radii match existing card pattern

- DemoTierSwitcher pill: **8px uniform padding** (top/bottom/left/right all 8px); outer gap between buttons 4px. No 6px value is declared or used.

Source: ResultsMap.jsx `.wrap{padding:30px 24px}`, `.row{padding:12px 14px}`, Landing.jsx `.panel{padding:20px}`.

**Primary visual anchor — ResultsMap free-tier screen:**

The city name renders in Instrument Serif at heading scale and the match-% chip uses `--accent` background — these two elements together are the dominant visual at that hierarchy level and the key attention target before any locked content is encountered.

### Empty State (FrostedSkeleton)

When a section is unlocked but the underlying Phase 7/6 component is not yet built on this branch:

**Heading:** (none — the skeleton renders as blurred placeholder lines, not text)
**Visual:** 4 skeleton lines at static widths `[85%, 70%, 90%, 60%]`, height 14px, radius 6px, background `rgba(243,237,225,0.06)`, inside a card with `var(--card)` background and `var(--border)` border.

This is the "graceful degradation" state (D-03). The skeleton looks locked-but-populated. No explicit empty state copy is needed — the frosted skeleton communicates "content coming" without text.

### Error State

**Not applicable.** Phase 8 makes no network calls and has no server-side access control (RESEARCH.md Security Domain section). There are no error states from network failures in this phase. Any errors from underlying Phase 5 live-AI calls are handled by Phase 5's existing golden-path fallback, not by the Phase 8 gate layer.

### Destructive Actions

**None.** No destructive actions exist in Phase 8. There is no delete, no irreversible state change, no payment processing, and no account persistence. Tier switching is freely reversible. Source: CONTEXT.md Deferred section — "no real auth, no account persistence."

### Modal Dismiss

The PricingModal close action is labeled **"Dismiss"** — a single-word conventional close label. This is the accepted convention for modals with no pending state change; no rename is required.

## Interaction Contract

### Blur-Dissolve Unlock Animation (D-09)

When a section transitions from locked to unlocked:
- Content wrapper: `filter: blur(8px)` → `filter: blur(0px)`, transition `0.42s ease`
- Lock overlay: `opacity: 1` → `opacity: 0`, transition `0.38s ease`
- Only `filter` and `opacity` are animated — no `height`, `margin`, `padding`, or `transform: translate`
- `will-change: filter` added to content wrapper at transition start, removed after 450ms
- `prefers-reduced-motion` guard: if `window.matchMedia("(prefers-reduced-motion: reduce)").matches`, snap directly to unlocked state with no transition

Source: RESEARCH.md Pattern 2 (LockGate) + Pattern 3 (CSS Blur). Same `prefers-reduced-motion` guard already used in Landing.jsx.

### LockGate Click Behavior

Clicking anywhere on a locked section (padlock icon or overlay background) opens PricingModal. No micro-confirmation — one tap = modal opens.

### DemoTierSwitcher Visibility (D-05 — Hidden Presenter Mode)

- Hidden by default (`visible={false}`). Judges see no switcher.
- Revealed by bottom-right corner triple-tap: hotspot is the 80×80px region at `(window.innerWidth - 80, window.innerHeight - 80)`. Three taps within 600ms toggle presenter mode on/off.
- Works on both mouse click and touchstart (D-13 — responsive).
- Gesture listener attached at `PotentialApp.jsx` root to persist across all step changes.

Source: RESEARCH.md Pattern 4.

### PricingModal Entry/Exit

- Entry: `opacity: 0 + translateY(10px)` → `opacity: 1 + translateY(0)`, transition `0.4s cubic-bezier(.22,.61,.36,1)`
- Exit: reverse
- Body scroll-locked while open: `document.body.classList.add("lp-locked")` (reuses existing Landing.jsx class)
- Click outside modal card closes it; "Dismiss" button closes it; selecting a tier (via CTA button) closes it and sets the new tier

Source: RESEARCH.md Pattern 5 (Landing.jsx `.panel` idiom).

### Responsive Breakpoint

- PricingModal tier grid: 4 columns on ≥521px; single column with Plus card first (`order: -1`) on ≤520px
- Testimonial grid: 3 columns on ≥521px; single column on ≤520px
- DemoTierSwitcher labels: full text ("Free", "Basic", "Plus", "Premium") on ≥400px; abbreviated ("Fr", "Ba", "+", "★") on <400px
- Implemented via scoped `<style>` tags inside each component (matches ResultsMap.jsx `@media(max-width:560px)` pattern)

Source: RESEARCH.md Responsive Design section + D-13.
